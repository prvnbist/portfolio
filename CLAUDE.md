# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is pnpm.

- `pnpm dev` / `pnpm build` / `pnpm start` — Vite + TanStack Start (`vite dev`, `vite build`, `node .output/server/index.mjs`)
- `pnpm lint` — `biome lint ./src`
- `pnpm format` — `biome format --write .` (tabs, width 3, single quotes, no semicolons, line width 100)
- `pnpm precommit` — format + lint

There is no test suite.

## Architecture

Personal portfolio/blog (prvnbist.com). TanStack Start (file routes in `src/routes/`, generated `src/routeTree.gen.ts`) on Vite + Nitro, React 18, Tailwind CSS v4, Biome; `@/*` maps to `src/*`. (Migrated from Next.js; see `MIGRATION.md` for history.)

**Content is entirely local — there is no CMS or external content API.**
- **Articles:** `src/articles/*.mdx` hold body and frontmatter (`title`, `date`, `tags`, `description`, `ogImage`). MDX is compiled at build time by `@mdx-js/rollup` (custom wrapper in `vite.config.ts` that skips `?raw`/query imports so frontmatter can be read from source with `gray-matter`). `src/lib/articles.server.ts` derives the blog index, tag list and prev/next links from frontmatter; `src/routes/blog/$slug.tsx` renders the article, with `CodeBlock` using prism-react-renderer. Adding an article is just adding an `.mdx` file; the filename is the URL slug (`/blog/<slug>`). Article images live in `public/images/articles/<slug>/`.
- **Designs and projects:** typed static data in `src/data/designs.ts` and `src/data/projects.ts` (thumbnails under `public/images/`); home-page timelines are constants in `src/routes/index.tsx`.

Only `VITE_`-prefixed env vars reach the browser (`VITE_GOOGLE_ANALYTICS`). `.env` is tracked in git; only `.env*.local` is ignored. No network access is needed to build or run.

**Blog listing** (`src/routes/blog`): search (`?s=`, case-insensitive title substring) and tag filter (`?tag=`) are URL search params validated by the route and passed to the `getBlogIndex` server function in `src/lib/articles.ts`, which filters the frontmatter-derived list on the server via `filterArticles`.

**Styling (Tailwind v4):** CSS-first config — there is no `tailwind.config.ts` or PostCSS config. Tailwind loads via `@tailwindcss/vite` in `vite.config.ts`; the entry is `src/app/globals.css` (`@import "tailwindcss"` plus an `@theme` block for the custom `dark-*`/`blue-*` colors). Gotcha: v4 utilities live in `@layer utilities`, so any *unlayered* global rule (e.g. `* { margin: 0 }`, `a { color }`) overrides them (this broke `mx-auto`/padding centering). Put global element rules inside `@layer base`. Also note v4 renames: `rounded` → `rounded-sm`, `outline-none` → `outline-hidden`, `bg-gradient-to-*` → `bg-linear-to-*`, `flex-shrink` → `shrink`.

**Other:** `src/routes/script.ts` proxies the self-hosted analytics script at `/script`; Google Analytics is injected in the root route `head()`. `sitemap[.]xml.ts` and `robots[.]txt.ts` in `src/routes/` are generated server routes. Shared UI lives in `src/components/`; page-specific pieces are in `src/app/` (`blog`, `code`, `design`, `sections`), and layout chrome such as the Navbar in `src/sections/`. Static project data is in `src/data/`.

**Setup:** `cp .env.example .env` (optional; only sets `VITE_GOOGLE_ANALYTICS`). `package.json` pins Node 26.x. `src/routeTree.gen.ts` is generated by the TanStack router plugin; don't edit it by hand.
